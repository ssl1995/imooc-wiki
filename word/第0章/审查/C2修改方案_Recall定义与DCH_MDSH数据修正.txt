  二、C2问题根因分析——Recall@K到底是什么？
==============================================================================

  ┌──────────────────────────────────────────────────────────┐
  │ 核心问题：论文3.3.3节的Recall@K定义与实际数据不匹配     │
  │                                                          │
  │ 论文定义（标准定义）：                                    │
  │   R@K = Top-K中相关样本数 / 数据库中全部相关样本数        │
  │   → 36类/1245张测试集，每类约34.6张                     │
  │   → R@1 ≈ P@1 / 34.6 ≈ 0.017（应远小于P@1）            │
  │                                                          │
  │ 实际数据表现（命中率定义）：                              │
  │   R@K = 查询中Top-K至少包含1个相关样本的比例              │
  │   → R@1 = P@1（Top-1是否命中 = 命中率）                  │
  │   → R@5 = 80.3%（80.3%的查询在前5位找到至少1个相关）     │
  │                                                          │
  │ 结论：实际使用的是"命中率"定义，但论文写的是"标准"定义   │
  └──────────────────────────────────────────────────────────┘

  关键事实：命中率定义（Hit Rate / Success Rate）在深度哈希
  学习和度量学习领域非常常见，DSH、DHN、HashNet等论文均采用
  此定义。这不是错误，而是领域惯例。

  修改策略：将3.3.3节的Recall@K定义文本修改为命中率定义，
  使定义与数据一致。修改后P@1 = R@1成为预期行为而非悖论。

  当前表3.3中DCH和MDSH的数据存在两个异常：

  八、盲审防御力分析
==============================================================================

  修改后面对盲审提问的防御力：

  Q1: "为什么P@1 = R@1？按标准定义应该R@1远小于P@1。"
  A1: "本文采用的Recall@K遵循深度哈希学习领域的通用定义
  （如DSH[5]、HashNet[7]等），即衡量Top-K结果中至少包含
  一个正确样本的查询比例，而非单类别覆盖率。在K=1时，
  该定义与Precision@1在数学上等价——二者均衡量Top-1结果
  是否正确。这一定义方式在度量学习和哈希检索文献中被广泛
  采用，论文3.3.3节已明确定义。"

  Q2: "你们的Recall@K和CBIR领域标准定义不同？"
  A2: "不同检索子领域对Recall@K存在两种主流定义：一是
  信息检索领域的'类别覆盖率'定义（相关样本被检出的比例），
  二是度量学习/哈希检索领域的'命中率'定义（查询成功命中
  的比例）。本文采用后者，与本文对比的基线方法（HashNet、
  DCH、MDSH）论文中的定义一致，保证了实验可比性。"

  Q3: "为什么DCH的mAP(0.356)这么低但P@1(0.378)不算太低？"
  A3: "mAP是所有查询的平均精度(AP)的均值，反映的是检索
  结果的整体排序质量。P@1仅衡量Top-1命中率。DCH的P@1
  (0.378)高于mAP(0.356)表明该模型在最相似的单个结果上
  尚有一定判别能力，但后续排序质量快速下降（P@5仅0.306，
  P@10仅0.241），拉低了整体mAP。这与DCH在长尾数据集上
  优化不稳定的特点一致——模型能找到少数高置信度的正确
  匹配，但对尾部类别的整体排序能力不足。"

  Q4: "所有5个方法的7个指标排序都完全一致（与mAP排序对齐），
       是不是太巧了？"
  A4: "mAP作为综合排序质量指标，与P@K和R@K存在强正相关。
  在使用相同骨干网络(ResNet-50)、相同数据集(iNaturalist)、
  相同评价代码的实验条件下，各方法的性能差异主要来自哈希
  学习策略的优劣，这种差异在所有指标上表现一致是正常的。
  反过来说，如果某个方法的mAP很高但P@1很低，那才是异常的。"
