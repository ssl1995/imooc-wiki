=== Para 263 ===
本章首先阐述DHLM模型设计的背景，分析现有图像检索方法在古树名木应用场景中的局限性。然后详细介绍DHLM模型的整体架构设计，包括图像与位置特征编码层、多模态融合层、哈希层和检索层四个核心模块，重点阐述多路融合策略验证过程与双分支哈希投影机制（Dual-branch Hash Projection, DBHP）的设计动机，并设计多损失联合优化策略贯穿训练过程。为验证模型的有效性，本章选取iNaturalist 2018公开数据集和自建BFATH数据集开展实验，详细说明数据预处理流程、评价指标定义和模型参数设置。最后通过与HashNet等三个基线模型的对比实验，融合策略对比实验、消融实验和超参数敏感性分析，深入分析DHLM模型的性能表现与优越性，为古树名木图像检索任务提供高效可靠的算法支撑。

=== Para 264 ===
3.1 引言

=== Para 265 ===
随着古树名木保护工作的深入推进，如何高效、准确地从海量图像数据库中检索出目标古树名木信息，成为当前研究的重要课题。传统的基于文本关键词的检索方式依赖人工标注，存在标注成本高、主观性强等问题，已难以满足实际应用中以图搜图的需求。基于内容的图像检索（Content-Based Image Retrieval, CBIR）技术通过提取图像特征进行相似度匹配，为解决这一问题提供了有效途径[40]。

=== Para 266 ===
深度哈希学习（Deep Hashing Learning）作为一种新兴的图像检索技术，近年来受到学术界和工业界的广泛关注。现有方法如HashNet通过连续松弛策略解决离散优化问题，DCH[41]引入Cauchy分布提升哈希码判别性，MDSH[42]采用多尺度深度监督实现高精度检索。然而，现有方法在古树名木图像检索任务中仍面临挑战：一方面，古树名木图像具有树种间形态相似、同树种内差异大的特点，单一图像特征难以捕捉细微判别性特征；另一方面，现有方法多采用单一损失函数优化，难以同时兼顾特征判别性与哈希码质量，且忽略了地理位置元数据对相似性判断的重要价值。针对上述问题，本章提出一种基于深度哈希学习的多模态图像检索模型DHLM（Deep Hashing Learning Multi-modal Network）。该模型设计轻量化的位置编码器将地理位置元数据融入图像特征，通过多损失联合优化策略同步提升特征判别性与哈希码质量，并采用多级检索策略兼顾检索效率与精度。需要说明的是，Space2Vec[16]和GeoCLIP[20]等方法聚焦于地理定位任务，不涉及哈希码生成与检索；本文DHLM的差异化在于将位置编码引入深度哈希检索框架，通过二进制哈希码实现存储压缩与检索加速。

=== Para 267 ===
综上所述，本章的主要工作如下：

=== Para 268 ===
（1）提出一种融合图像与地理位置元数据的深度哈希检索模型DHLM。该模型采用ResNet等多骨干网络提取图像特征，设计MLP位置编码器将地理位置元数据编码为特征向量；通过多路融合策略验证确定特征拼接为融合方案；设计双分支哈希投影机制，将图像特征与位置特征分别映射至128维哈希语义空间后加权融合，最终生成紧凑的二进制哈希码以实现高效检索。

=== Para 269 ===
（2）设计多损失联合优化与难例挖掘策略。采用Triplet Loss、Contrastive Loss和Quantization Loss的联合优化策略，通过权重调节实现特征判别性、样本对相似度关系和哈希量化误差的同步优化；结合在线难例挖掘机制动态选择困难样本，有效缓解古树名木数据集的类别不平衡问题。

=== Para 270 ===
（3）在iNaturalist 2018和自建BFATH数据集上进行实验验证。通过与HashNet、DCH、MDSH三个基线模型的对比实验，以及损失函数组合、难例挖掘策略等多维度的消融实验，验证DHLM模型的有效性和合理性。

=== Para 271 ===
3.2 模型结构设计

=== Para 272 ===
3.2.1 模型整体结构

=== Para 273 ===
DHLM模型首先采用双分支特征提取网络分别对图像和地理位置进行特征表示，以保证图像特征与位置特征具有互补性，同时将多模态数据处理为可以建模和计算的向量化形式。

=== Para 274 ===
在特征提取过程中，图像分支借助ResNet-50等主流卷积神经网络提取高层语义特征（即图像特征），位置分支则采用轻量化的多层感知器将位置坐标编码为固定维度的位置特征向量。

=== Para 275 ===
在多模态融合阶段，通过特征拼接将图像特征与位置特征融合，生成包含双模态信息的融合特征（融合策略的详细论证见3.2.3节）。

=== Para 276 ===
在哈希生成阶段，设计双分支哈希投影机制，将图像特征与位置特征分别映射至128维哈希语义空间，通过可学习权重在哈希空间进行加权融合，最终生成紧凑的二进制哈希码；并结合多损失联合优化策略约束哈希码质量。

=== Para 283 ===
图像与位置特征编码层

=== Para 284 ===
为获取高质量的图像特征和地理位置特征，首先采用双分支结构对多模态数据进行特征表示。其中，图像分支选用ResNet-50主流骨干网络进行图像特征提取，通过卷积操作捕获古树名木的图像数据，输出固定维度的图像特征向量。地理位置分支设计轻量化的LocationEncoder编码器，采用多层感知器（MLP）结构将二维地理位置坐标（纬度、经度）映射为高维位置特征向量，以建模古树名木的空间分布属性。两个分支独立工作，分别输出图像和位置的特征向量，为后续多模态融合提供基础。

=== Para 285 ===
多模态融合层

=== Para 286 ===
多模态融合模块对图像特征和位置特征进行有效整合。主模型采用特征拼接方法，将图像特征向量与位置特征向量直接拼接，构建出包含双模态信息的融合特征向量。为系统性地论证融合策略的选择，本文在iNaturalist 2018验证集上对比了特征拼接、门控融合、逐元素相加和逐元素相乘四种方案，详细实验结果与论证见3.4.2节与表3.6。

=== Para 287 ===
哈希层

=== Para 288 ===
哈希层负责将融合特征向量映射为紧凑的二进制哈希码，以实现高效的近似最近邻检索。该层采用双分支哈希投影机制（DBHP），将图像特征与位置特征分别通过独立投影矩阵映射至128维哈希语义空间，再通过可学习权重在哈希空间进行加权融合；在训练阶段输出连续值，并通过量化损失约束减小与离散哈希码之间的量化差距；在推理阶段通过符号函数（Sign）将连续值量化为二进制哈希码，最终生成128位二进制哈希码。哈希层的详细设计与数学表达见3.2.4节。

=== Para 289 ===
检索层

=== Para 290 ===
检索层负责根据查询（图像或地理位置坐标）从数据库中返回最相似的Top-K个检索结果，支持以图搜图（I2I）、以图搜位置（I2L）和以位置搜图（L2I）三种检索模式。基于汉明距离的哈希码快速检索利用二进制哈希码的异或运算实现常数时间复杂度的高效筛选；基于余弦相似度的浮点特征精检索通过计算特征向量间的余弦相似度实现精确排序；多级检索策略则采用“哈希粗排+浮点精排”的两阶段机制，兼顾检索效率与精度。

=== Para 312 ===
3.2.4 哈希层

=== Para 313 ===
深度哈希学习的核心挑战在于如何将高维连续特征映射为紧凑的二进制哈希码，同时保持语义判别性和训练可优化性。现有方法如HashNet[7]采用FC-Tanh-Sign结构实现连续松弛，但将多模态拼接特征直接通过单层全连接投影至哈希空间，存在两方面局限：（1）高维混叠，不同模态信息在投影过程中相互干扰，导致各模态的独立语义被稀释；（2）不可解释，单一路投影无法反映各模态对最终哈希码的独立贡献。

=== Para 314 ===
针对上述问题，受现有图像-文本多模态哈希方法独立投影思想的启发[9-10]，本文针对图像-地理位置坐标场景设计双分支哈希投影融合机制（DBHP），结构如图3.1的哈希层所示。其核心思想是：将图像特征与位置特征分别通过独立投影矩阵映射至128维哈希语义空间，再在哈希空间进行显式加权融合。该设计的优势在于：（1）模态解耦，各模态在投影过程中保持独立，避免混叠干扰；（2）可解释性，融合权重λ直接反映模型对图像模态与位置模态判别力的动态评估。

=== Para 354 ===
在线难例挖掘在每个训练批次中动态选择当前模型最难区分的Top-K个样本参与损失计算，使模型更关注决策边界附近的模糊样本。这种策略对类别不平衡场景尤为有效：对于样本稀少的尾部类别（如濒危古树名木），难例挖掘确保其样本获得足够的梯度更新，避免被头部类别主导。

多级检索策略

=== Para 370 ===
为兼顾检索效率与精度，本文设计了“哈希粗排+浮点精排”的多级检索策略。本实验采用余弦相似度检索作为主评估方案，哈希码检索效率验证见3.4.2(3)节。第一阶段利用汉明距离的常数时间计算优势，从全部库样本中快速筛选出Top-M候选集（通常M取总样本数的10%至20%）；第二阶段对候选集使用余弦相似度进行精确重排序，返回最终的Top-K结果。

=== Para 371 ===
需要特别说明的是，在Location-to-Image（L2I）检索模式下，查询输入为位置坐标而非图像。此时，查询端仅激活LocationEncoder分支，将输入坐标编码为256维位置特征向量，经哈希层生成位置哈希码；数据库端则存储了所有图像样本经图像分支编码后的图像哈希码（预计算存储）。检索时，在统一的哈希空间中寻找与查询位置哈希码最近邻的图像哈希码，返回对应图像。图像分支在L2I查询阶段不参与编码，但在数据库构建阶段承担了所有图像样本的哈希码预计算生成，是L2I检索能力的基础保障。

=== Para 372 ===
3.3 实验条件与环境设置

=== Para 373 ===
3.3.1 数据集描述

=== Para 374 ===
本研究实验采用两个数据集：iNaturalist 2018数据集和自建BFATH数据集。iNaturalist 2018数据集提供大规模带位置坐标的植物和古树名木图像，适用于模型训练与对比实验；BFATH数据集来源于《京津冀古树寻踪》[44]书籍数字化，用于模型微调与系统演示。

=== Para 375 ===
（1）iNaturalist 2018数据集

=== Para 376 ===
iNaturalist 2018数据集由加利福尼亚理工学院visipedia研究团队发布，作为CVPR 2018 FGVC5（Fine-Grained Visual Categorization）workshop的官方竞赛数据集公开发布[21]。该数据集通过iNaturalist众包平台（https://www.inaturalist.org）全球收集，原始发布形式为图像文件配合JSON标注文件（train2018.json、val2018.json）。原始数据量如下：训练图像437513张、验证图像24426张、测试图像149394张，涵盖8142个物种类别，覆盖植物界（Plantae）、昆虫纲（Insecta）、鸟纲（Aves）等14个超类；其中植物界包含2917个物种、118800张训练图像和8751张验证图像。数据集图像经统一缩放处理（最大边800像素），以JPEG格式存储，训练集与验证集图像总量约120GB。原始标注文件采用COCO数据集格式，每张图像的JSON记录包含id、file_name、category_id、license等核心字段；物种分类信息通过category字段提供完整的生物学分类层级，包含界（kingdom）、门（phylum）、纲（class）、目（order）、科（family）、属（genus）、种（species）七个层级。需要特别说明的是，iNaturalist 2018原始发布的标注文件（train2018.json / val2018.json）中的分类学名称经混淆处理（obfuscation），无法直接读取真实科属名。2018年6月，官方发布了解混淆文件categories.json.tar.gz，本研究使用该文件替换原始categories列表，获取真实的科属名称用于后续筛选。

=== Para 377 ===
2019年8月，官方额外发布了地理位置补充文件inat2018_locations.zip（约11MB），该文件通过image_id与原始标注文件建立关联，为训练集和验证集中的每张图像补充了latitude（纬度）、longitude（经度）、loc_uncert（米）、date（拍摄日期）和user_id（上传用户标识）五个字段。本研究的数据构建流程如下：

=== Para 378 ===
步骤1：数据获取与解混淆。iNaturalis官方GitHub仓库（https://github.com/visipedia/inat_comp/tree/master/2018）获取全部训练集与验证集图像、JSON标注文件以及地理位置补充文件。使用官方发布的解混淆categories列表替换原始混淆的category名称，建立image_id到真实family字段的映射关系。

=== Para 379 ===
步骤2：古树名木相关科属筛选。本研究依据《古树名木普查技术规范》[52]及京津冀地区常见古树名木科属[44]分布，从植物界（Plantae）的2917个物种类别中，通过family（科）字段筛选出以下25个相关科属类别：松科（Pinaceae）、柏科（Cupressaceae）、壳斗科（Fagaceae）、豆科（Fabaceae）、榆科（Ulmaceae）、樟科（Lauraceae）、木兰科（Magnoliaceae）、无患子科（Sapindaceae）、蔷薇科（Rosaceae）、木犀科（Oleaceae）、杨柳科（Salicaceae）、胡桃科（Juglandaceae）、桑科（Moraceae）、柿树科（Ebenaceae）、大戟科（Euphorbiaceae）、紫葳科（Bignoniaceae）、芸香科（Rutaceae）、苦木科（Simaroubaceae）、五加科（Araliaceae）、紫茉莉科（Nyctaginaceae）、海桐科（Pittosporaceae）、金丝桃科（Hypericaceae）、红豆杉科（Taxaceae）、棕榈科（Arecaceae）、禾本科（Poaceae）。需要说明的是，部分传统科属（如苏木科Caesalpiniaceae、七叶树科Hippocastanaceae、椴树科Tiliaceae）在iNaturalist 2018采用的Catalogue of Life 2018分类体系中已分别并入豆科、无患子科和锦葵科，本研究以数据集中实际存在的科属名称为准。经此步筛选，原始匹配到600个物种、29595张图像（训练集27795张、验证集1800张）。

=== Para 380 ===
步骤3：坐标有效性筛查。iNaturalist为众包数据集，位置坐标存在三类典型质量问题：定位设备精度差异显著（部分记录误差达数公里）、早期观测未开启GPS导致坐标空值、以及设备漂移导致坐标落在海洋等非植被区域。因此本研究对位置坐标进行四步有效性筛查：坐标基础验证，剔除latitude或longitude字段缺失及明显越界（纬度超出[-90, 90]、经度超出[-180, 180]）的记录；定位不确定性阈值筛选，保留loc_uncert ≤ 200米的记录，该阈值覆盖消费级GPS在开阔地（5-50米）和城市峡谷（50-200米）的典型精度范围，同时有效剔除基站定位漂移及手动输入错误，此步保留率约83.2%；研究区域聚焦，保留北美东部温带区域（经度-100°W ~ -60°W，纬度25°N ~ 50°N）的观测记录，该区域是iNaturalist数据中木本植物观测最密集、多样性最丰富的地带，具有代表性的温带落叶阔叶林和混交林生态系统，通过全球海岸线矢量数据剔除落在海洋、大型湖泊中的坐标；物种样本量保障，剔除训练样本量<15张的稀有物种，确保每个保留物种具有足够的训练样本用于深度学习模型收敛。经上述筛查，最终保留197个物种、12544张具有有效坐标的图像数据。

=== Para 381 ===
iNaturalist 2018中的位置坐标由拍摄者移动设备GPS自动记录，定位精度因设备与环境差异存在波动，属于消费级定位精度，满足本研究城市/景区级位置检索的管理单元尺度需求。本研究使用该数据集中的图像数据及其对应的位置坐标构建训练样本，物种标签仅用于Triplet Loss监督信号。需要说明的是，iNaturalist 2018为通用植物观测数据集，其图像采集场景以野外自然生境为主，样本分布与真实古树名木行政记录在树龄、保护级别等维度上存在差异，因此本研究将其定位为“预训练与通用评估数据集”，主要服务于模型初始化和跨数据集泛化能力验证，而非直接作为古树名木场景的最终评估标准。

=== Para 382 ===
综上所述，将上述12544张古树名木相关图像按约7:2:1比例划分为训练集（8781张）、验证集（2509张）和测试集（1254张）。为避免数据泄露，划分时基于image_id进行去重处理，确保同一棵树的多张图像（若存在）仅归属于单一集合，不跨集分布。

=== Para 383 ===
（2）BFATH自建数据集

=== Para 384 ===
BFATH（Beijing Forestry Ancient Tree Hashing）是本研究专门针对古树名木场景构建的领域验证数据集，作为论文核心实验的评估基准与系统演示数据源。其数据来源为《京津冀古树寻踪》[44]，该书由京津冀古树名木保护研究中心编著，中国建筑工业出版社2019年出版，全书363页彩图，系统收录了京津冀三地经官方认定的古树名木资源。该书于2020年获中国风景园林学会科学技术奖三等奖，其编撰团队沿古树踪迹实地踏查三地重要古树，查阅《村志》《碑志》《史志》等历史记载并走访当地村民，记录每株古树的生长位置、测量树高和胸径，拍摄花果特征及不同季节景观，具有高度的权威性与专业性。书中收录古树群14个、古树名木约190株，其中北京25科37属44种107株、河北11科25属51种、天津4科4属4种，基本涵盖了三地代表性古树树种。每株古树均经过专家鉴定，符合《古树名木普查技术规范》[52]中关于古树（树龄≥100年）或名木（具有历史/文化/科学价值）的认定标准。

=== Para 385 ===
本研究的数据构建流程如下：步骤1，书籍数字化与图像提取。使用高精度扫描仪（分辨率≥600 dpi）对书中古树图像进行数字化采集，确保原始印刷质量无损转换；对每株古树的文字描述页同步进行OCR识别，提取位置信息字段；步骤2，位置坐标获取与验证。书中记录的古树位置为文字描述形式（如“北京市门头沟区潭柘寺”），需通过地理编码服务将其转换为WGS84经纬度坐标；保留地理编码精度<100米的样本，剔除乡镇级及以下模糊位置；步骤3，样本筛选与标注审核。基于以下三条标准进行严格筛选：图像质量，即分辨率≥512×512，画面清晰、古树主体完整；坐标精度，即地理编码精度<100米，人工核验通过；③物种确认，即与书中专家鉴定结果一致，由人工核对物种标签。经筛选后，最终纳入数据集的有效样本为300张，涵盖银杏、侧柏、桧柏、油松、国槐、青檀、黄连木、柘树、流苏、杜梨、板栗、漆树、榉树、梨树、红桦共15个典型树种。

=== Para 386 ===
上述15个树种中，银杏、侧柏、桧柏、油松、国槐为京津冀地区最常见且最具代表性的古树树种，青檀、黄连木、柘树、流苏等为北京地区稀有古树树种，板栗、漆树、榉树等反映了河北山区古树的多样性。从书中约190株古树的500余张候选图像中，经上述三步筛选后保留300张有效样本。BFATH按8:1:1比例划分：训练集240张（80%）、验证集30张（10%）和测试集30张（10%）。

=== Para 387 ===
BFATH数据集的核心价值在于：权威性，数据来源为官方认定古树名木，符合《古树名木普查技术规范》[52]的行政定义；专业性，涵盖树龄、树高、保护级别等古树名木特有属性字段；独立性，与iNaturalist众包数据源完全独立，无样本重叠，可有效验证模型的领域迁移能力。需要说明的是，古树名木为不可再生资源，受保护政策限制，大规模数据采集成本极高；本书收录的约190株古树经多图扩展后获得500余张候选图像，经严格筛选后保留300张带精确位置坐标的权威标注样本，已属稀缺资源。为缓解小样本对实验结论的影响，本文采用“iNaturalist预训练+BFATH微调”的迁移学习策略降低对小样本的依赖。BFATH在本文中的职能定位为：领域微调，在iNaturalist预训练模型基础上，使用BFATH训练集进行有监督微调，验证模型在真实古树名木数据上的迁移能力；系统演示，作为第4章系统演示数据源，树龄、树高等字段仅用于系统功能界面展示，不参与任何模型训练与计算过程。

=== Para 388 ===
综上所述，iNaturalist 2018数据集作为主要实验数据，BFATH数据集用于领域微调与系统演示。

=== Para 389 ===
3.3.2 数据预处理

=== Para 390 ===
为提升模型对古树名木图像的特征提取能力与检索鲁棒性，降低拍摄角度、光照变化、背景干扰及样本不平衡等因素对检索性能的影响，本研究对数据集进行标准化预处理。整体流程包含图像变换、数据增强、像素归一化、地理位置元数据预处理四个核心环节，具体实现如下：

=== Para 391 ===
图像变换

=== Para 392 ===
为适配深度哈希学习模型的输入规范，消除图像分辨率不一致带来的计算冗余与特征偏差，所有训练、验证及测试图像均统一缩放至224×224像素。缩放过程采用双线性插值算法，在降低分辨率的同时保留古树名木枝干形态、纹理、冠形等关键图像特征，保证图像结构完整性与语义一致性。注：本研究默认使用224×224作为统一输入尺寸，与ResNet-50等主流骨干网络兼容。

=== Para 393 ===
数据增强

=== Para 394 ===
针对古树名木数据集存在的样本分布不均、拍摄场景多样、视角单一等问题，在模型训练阶段引入在线数据增强[45]策略，以扩充有效样本多样性、提升模型泛化能力。具体增强参数设置如下：随机水平翻转：概率0.5；随机旋转：角度范围[-15°, +15°]（保守设置，避免树冠方向混乱）；随机裁剪：裁剪比例[0.8, 1.0]，保持长宽比（保护挂牌信息不被过度裁剪）；颜色抖动：亮度±0.2、对比度±0.2、饱和度±0.2、色相±0.1（保守设置，保留树皮纹理特征）。测试阶段仅执行图像缩放和归一化。

=== Para 395 ===
归一化

=== Para 396 ===
为加速模型收敛并匹配预训练模型的特征分布，所有图像在输入网络前均采用ImageNet预训练模型的标准归一化参数：均值μ=[0.485, 0.456, 0.406]，标准差σ=[0.229, 0.224, 0.225]。该操作可将图像像素值映射至标准分布区间，消除不同图像间的灰度与色彩差异，提升特征提取的稳定性与训练效率。

=== Para 397 ===
地理位置元数据预处理

=== Para 398 ===
鉴于本研究采用图像与地理位置元数据多模态融合，位置坐标需进行如下预处理：坐标归一化，将原始WGS84坐标（范围：纬度[-90, 90]，经度[-180, 180]）线性映射至[-1, 1]区间，以匹配神经网络输入要求；异常值检测：剔除坐标明显异常（纬度超出[-90,90]、经度超出[-180,180]）及定位不确定性（loc_uncert）大于200米的样本；剔除水生植物、温室盆栽等非野外生长场景的类别。；缺失值处理：本研究在数据筛选阶段已剔除缺失坐标样本，所有用于实验的12544张图像均具有有效位置坐标，无需额外缺失值处理。

=== Para 399 ===
3.3.3 评价指标

=== Para 400 ===
为全面地评估深度哈希学习模型在古树名木多模态检索任务中的性能，研究采用图像检索领域通用的标准评价指标[46]，并针对哈希码特性与双向检索任务进行扩展。

=== Para 401 ===
（1）mAP@K（mean Average Precision at K）

=== Para 402 ===
平均精度均值，是衡量图像检索整体精度的核心指标。该指标先计算每个查询样本在前K个检索结果中的平均精度（AP），再对所有查询样本取均值得到mAP@K。此处查询样本的相关性判定基于物种标签（同类别视为相关），但计算过程是对查询样本而非类别进行平均。mAP数值越高，表明模型对不同类别古树名木的检索准确性越高。

=== Para 403 ===
Recall@K（Top-K召回率）

=== Para 404 ===
Top-K召回率，用于衡量模型检索的命中能力。其含义为：在所有查询中，模型返回的Top-K个最相似结果中至少包含一个正确相关样本的查询所占比例。Recall@K越高，说明模型越能在前K位结果中成功命中目标类别，漏检率越低。以iNaturalist 2018测试集为例，该子集包含25个古树名木相关类别、1254张测试样本，平均每类约34.6张。BFATH测试集规模较小（30张），因此在评价指标说明中以iNaturalist为例阐述计算方法。该定义与DSH、HashNet等深度哈希学习文献的评价方式一致。需要说明的是，当K=1时，Recall@1与Precision@1在数值上相等。这是上述定义下的数学恒等关系：Top-1仅返回一个结果，“至少包含一个相关样本”等价于“该结果为相关样本”，二者的判定条件完全一致。当K>1时，两个指标呈现不同的度量特性：Precision@K随K增大而单调递减，反映检索结果中相关样本的纯度；Recall@K随K增大而单调递增，反映相关样本被成功命中的覆盖面。因此，Precision@K与Recall@K在K>1时提供互补的评价视角。本研究选取K∈{1,5,10}，该K值集合与DCH等基线论文一致，保证实验可比性。

=== Para 405 ===
Precision@K（Top-K精确率）

=== Para 406 ===
Top-K精确率，用于衡量模型检索的精准度。其含义为：在模型返回的Top-K个检索结果中，正确相关样本所占的比例。Precision@K越高，说明模型返回的前列结果可靠性越高，误检率越低。该指标与Recall@K结合，可评价检索结果的排序质量。

=== Para 407 ===
双向检索评价策略

=== Para 408 ===
本文采用双向检索评价策略，分别评估以图搜图、以图搜位置和以位置搜图三个检索任务的性能。

=== Para 409 ===
以图搜图（Image-to-Image，简称I2I）以图像数据为查询，在图像数据库中检索同类图像，采用标准图像检索指标mAP-I2I、Recall@K-I2I、Precision@K-I2I。

=== Para 410 ===
以图搜位置（Image-to-Location，简称I2L），以图像为查询，检索地理位置元数据。将返回的位置坐标与查询图像的真实位置计算地理距离，距离<1km视为相关样本，地理距离阈值设为1km，对应城市/景区级古树名木检索的管理单元尺度。计算mAP-I2L、Recall@K-I2L、Precision@K-I2L。

=== Para 411 ===
以位置搜图（Location-to-Image，简称L2I）利用位置哈希码与图像哈希码在同一哈希空间中的可比性，通过汉明距离度量位置查询与图像库样本的相似性。以地理位置坐标为查询，在图像数据库中检索相似图像数据。距离查询位置<1km的图像视为相关样本，计算mAP-L2I、Recall@K-L2I、Precision@K-L2I。

=== Para 412 ===
哈希码检索性能分析

=== Para 413 ===
为验证二进制哈希码的检索效率与精度，本研究补充以下对比分析：汉明距离检索，基于128位二进制哈希码的汉明距离计算Top-K检索结果与512维浮点特征的余弦相似度检索对比，量化哈希码的精度损失。

3.4 实验构建与结果分析

=== Para 426 ===
3.4.1 基线模型选择

=== Para 427 ===
为客观地评估本文所提出的DHLM在古树名木多模态检索任务中的有效性与先进性，本节在两个数据集上开展分层实验：首先在iNaturalist 2018数据集上进行预训练和通用性能评估，验证DHLM在通用植物检索场景中的基础能力；随后在BFATH古树名木数据集上进行领域微调和最终评估，验证模型在真实古树名木场景中的有效性。基线对比实验统一在iNaturalist 2018数据集上进行，以确保与现有文献的可比性；消融实验统一在iNaturalist 2018验证集上进行，以控制变量、精确量化各模块贡献。为确保实验结果的可重复性，本研究所有实验均采用固定的随机种子（seed=42）进行初始化，并在相同软硬件环境下独立运行。为确保方法间比较的公平性，本研究所有实验在固定随机种子（seed=42）和相同软硬件环境下运行，各方法使用相同的数据划分和评估代码。考虑到计算成本及领域惯例，本论文报告固定种子下的单次运行结果，核心结论已通过预实验多次验证确认稳定性。所有方法均使用相同的随机种子、相同的数据划分和相同的评估代码，确保方法间的相对比较公平可靠。核心结论（DHLM优于基线方法的性能排序）已通过预实验阶段的多次验证运行确认其一致性。上述实验设计明确区分了两个数据集的职能：iNaturalist 2018承担核心性能对比（表3.3）、融合策略对比（表3.6）与消融实验（表3.7），保证统计稳健性；BFATH承担领域微调验证与系统演示，关注模型在真实古树名木场景中的迁移有效性。

=== Para 428 ===
鉴于传统非深度学习方法（如LSH、SH）及早期深度哈希方法（如DHN）在特征表征能力上已显著落后于近年基于深度神经网络的方法，难以满足古树名木多模态检索的精度需求，故本文聚焦于近年的深度哈希代表性方法进行对比分析。为控制实验规模，本文优先选取各技术路线的开创性工作（HashNet/DCH）及截至2023年的SOTA（MDSH）进行对比，本节选取深度哈希领域中具有代表性的三个模型作为基线模型开展对照实验：

=== Para 429 ===
HashNet模型

=== Para 430 ===
2017年，Cao等[7]提出的深度哈希网络，首次引入连续松弛（Continuation）优化策略，以平滑函数逐步逼近符号函数，有效缓解哈希学习中的量化误差问题。HashNet奠定了连续松弛策略在深度哈希中的基础地位，是当前深度哈希研究的主流基线方法。

=== Para 431 ===
DCH模型

=== Para 432 ===
2018年，Cao等[41]同团队后续提出的深度Cauchy哈希方法，采用Cauchy分布拟合样本对相似度分布，利用其重尾特性设计成对损失函数；同时引入动态难例挖掘机制，自适应调整难例采样策略，显著提升模型对困难样本的判别能力。

=== Para 433 ===
MDSH模型

=== Para 434 ===
2023年，Wang等[42]提出的多尺度深度监督哈希方法，通过融合CNN不同阶段的多尺度特征，结合深度监督机制在多个语义层级学习判别性哈希表示。MDSH在多个公开数据集上取得优异性能。

=== Para 435 ===
上述基线方法涵盖连续松弛策略（HashNet）、动态难例挖掘（DCH）与多尺度深度监督（MDSH）三条技术路线，时间跨度从2017年至2023年，能够充分验证本文DHLM模型在深度哈希技术发展脉络中的创新性与先进性。

=== Para 436 ===
需要说明的是，上述基线方法均为单模态图像哈希方法，而DHLM为融合图像与地理位置元数据的多模态方法。为避免“多模态vs单模态”的对比不公平性，本文设计两组对照实验：

=== Para 437 ===
公平对比实验

=== Para 438 ===
为验证DHLM核心设计（哈希层结构、损失函数组合、难例挖掘策略）的有效性，本文构建DHLM的单模态变体DHLM-Image（即消融实验中的“w/o Location”配置，仅使用ResNet-50图像特征，去除LocationEncoder和位置分支）。DHLM-Image与HashNet/DCH/MDSH均为单模态图像哈希方法，且统一使用ResNet-50作为骨干网络，仅对比不同哈希学习策略的性能差异，构成对比基准。

=== Para 439 ===
多模态增益验证

=== Para 440 ===
为验证地理位置元数据融合带来的性能提升，本文对比DHLM（图像+位置双模态）与DHLM-Image（仅图像单模态）的性能差异，量化多模态融合的贡献。

=== Para 441 ===
本节基线对比实验、融合策略对比实验与消融实验统一在iNaturalist 2018数据集上进行，以确保统计稳健性和与现有文献的可比性；BFATH数据集承担领域微调验证与系统演示职能，具体见3.4.2节与第4章。上述对比策略既能公平评估DHLM核心设计的先进性，又能清晰展示多模态融合的价值，为古树名木多模态检索方法的选型提供全面参考。需要进一步说明的是，现有图像-文本多模态哈希方法（如DCMH[9]、SSAH[10]）的文本编码器（LSTM/BERT）针对离散文本设计，与地理位置坐标在输入格式、语义空间和编码方式上存在本质差异，直接迁移无法构成公平对比。受限于计算资源，本文构建 DHLM-Image 单模态变体作为内部公平基准，将上述多模态基线适配至图像-位置场景的对比实验留作后续研究。此外，近年来GeoCLIP等图像-位置对比学习方法通过CLIP跨模态对齐实现拍摄地理位置推断（Geo-localization），其任务目标为根据输入图像推断未知地理位置坐标，属于回归/分类任务；而DHLM面向数据库检索场景，通过哈希码快速匹配数据库中已知古树名木记录并返回其已有位置信息，属于检索任务。两者在任务定义、评价指标和应用场景上存在本质差异，因此不构成直接可比关系。DHLM的核心优势在于通过轻量级哈希编码实现毫秒级检索响应，适用于古树名木数据库的快速查询场景。

综合优势：DHLM通过“先进的单模态哈希设计+有效的多模态融合”双重优势，在iNaturalist 2018数据集上取得了优秀的检索性能。

=== Para 454 ===
这一显著性能提升主要归因于DHLM的以下方面创新：双分支哈希投影机制将图像特征与位置特征分别映射至128维哈希语义空间，通过可学习权重λ在哈希空间进行显式加权融合，既保留了各模态的独立判别语义，又实现了模态间的互补增强，有效缓解了单一图像特征在形态相似树种判别中的局限性；多损失联合优化通过Triplet Loss（三元组损失）、Contrastive Loss（对比损失）和Quantization Loss（量化损失）的协同作用，同步优化特征判别性、样本对相似度关系和哈希码量化质量；在线难例挖掘机制针对古树名木数据集的长尾分布特性，动态选择决策边界附近的困难样本进行重点学习，提升了模型对尾部类别的检索性能。

=== Para 455 ===
在基线方法的对比中，三个基线方法的性能排序与文献报告一致：HashNet（mAP 0.623）通过连续松弛策略奠定了深度哈希学习的优化基础；DCH（mAP 0.652）在HashNet基础上引入Cauchy分布和动态难例挖掘，提升了哈希码的判别性（提升2.9个百分点）；MDSH（mAP 0.685）通过融合多尺度特征和深度监督机制取得了三个基线中的最优性能（相比DCH提升3.3个百分点）。DHLM-Image取得mAP 0.713，优于最优基线MDSH（提升2.8个百分点），尽管所有方法均采用ResNet-50骨干网络和相同的训练配置，DHLM-Image通过联合损失函数的多目标协同优化和在线难例挖掘策略的动态样本选择，在特征判别性和哈希码质量两个维度上均获得了改善。具体而言，Triplet Loss与Contrastive Loss的联合使用使模型同时优化类间分离度和类内紧凑性，弥补了基线方法仅依赖单一损失函数的不足；OHEM策略则有效缓解了iNaturalist 2018数据集长尾分布下尾部类别训练不充分的问题。

=== Para 456 ===
综上所述，DHLM通过多模态融合、多损失联合优化和难例挖掘策略的协同设计，在古树名木单向检索任务中展现出较好的性能优势，验证了其在该应用场景中的合理性和有效性。

（2）双向检索性能对比

=== Para 458 ===
为进一步验证DHLM作为多模态检索模型的双向检索能力，本节评估Image-to-Location和Location-to-Image两个多模态检索方向的性能。本节在iNaturalist 2018测试集上分别评估Image-to-Image、Image-to-Location和Location-to-Image三种检索任务的性能。

=== Para 459 ===
实验结果见下表3.4所示。从实验结果可以看出，DHLM模型在三种检索任务上均展现出良好的检索性能。I2I任务作为传统图像检索方向，mAP达到0.741，与（1）节结果一致，验证了模型在图像特征判别上的有效性。I2L任务mAP为0.698，低于I2I任务（差距4.3个百分点）。这一性能差距源于三方面因素：首先，I2L属于多模态检索（图像→位置），需要建立图像特征与位置特征的多模态映射，本身难度高于同模态的I2I检索；其次，I2L是“高维→低维”映射（512维图像特征→2维坐标），信息压缩导致判别性下降；最后，地理距离阈值（<1km）引入判定噪声——同类别古树名木在野外分布中可能存在空间分离，同一位置范围内也可能存在不同树种，导致位置相关性的判定比图像相似性更具挑战性。尽管如此，I2L任务的Recall@5达到0.765，表明模型能够以较高概率在前五位结果中返回距离查询图像1km范围内的古树名木位置，验证了“以图搜位置”能力的有效性。L2I任务mAP为0.672，是三种任务中最低的。这一结果符合预期：L2I属于“低维→高维”检索（2维坐标→512维图像特征），从稀疏的位置信息推断丰富的图像内容本身具有更大的歧义性；同时，同一地理范围内可能存在多种古树名木，仅凭位置坐标难以精确区分。然而，Recall@5达到0.748表明，给定一个地理位置，模型能够有效检索出该位置附近的古树名木图像，满足“以位置搜图”的实际应用需求。

（3）哈希码检索效率验证

=== Para 467 ===

=== Para 468 ===
实验结果见下表3.5所示。128位哈希码汉明距离检索的mAP为0.712，相比512维浮点余弦检索（mAP 0.741）仅下降2.9个百分点，精度损失可控。这主要得益于训练阶段Quantization Loss的约束，使哈希层的连续输出趋近于±1，有效减小了Sign函数量化引入的信息损失。在检索速度方面，128位汉明距离的单次检索耗时仅为0.8ms（基于iNaturalist 2018测试集1254张样本库测量），相比浮点余弦检索（12.6ms）提升约15.8倍，得益于二进制异或（XOR）与位计数（POPCNT）指令的硬件加速优势。综合来看，128位哈希码在保持可接受检索精度的同时大幅降低了存储开销（128位 vs 512×32位=16384位，压缩比128:1）和检索时间，验证了深度哈希学习在古树名木大规模检索场景中的实用价值。

=== Para 481 ===
上述对比实验验证了DHLM相较于基线方法的性能优势。为深入分析模型各核心模块对检索性能的具体贡献，本节在iNaturalist 2018验证集（2509张）上设计消融实验。相比于BFATH测试集（30张），iNaturalist验证集样本量充足，统计波动显著降低，可为模块贡献提供更稳健的量化估计。本节设置以下五种模型配置：
