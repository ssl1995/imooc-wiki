一、ER图（图4.4-横向版v5-彩色.puml）问题
================================================================================

[必须修改] 1. 实体名称未与表名保持一致
   论文第4.2.3节文字明确使用以下表名：
     · 用户信息表（表4.1）
     · 图像表（表4.2）
     · 树木表（表4.3）
     · 权限角色表（表4.4）
   但ER图中实体名称为：
     · "用户信息" → 建议改为 "用户信息表"
     · "权限角色" → 建议改为 "权限角色表"
     · "树木信息" → 建议改为 "树木表"
     · "图像信息" → 建议改为 "图像表"
   修改位置：图4.4 PlantUML 中 4 个 entity 定义的名称。

[必须修改] 2. ER图中"树木信息"实体字段与实际树木表严重不符
   当前ER图中Tree实体仅列出：树种名称、树龄、树高、纬度、经度
   实际表有12个字段（见下方"树木表"差异），ER图应至少展示主要字段，
   且字段名应与表4.3保持一致。
   建议：要么扩展ER图Tree实体字段以匹配表4.3，要么修改表4.3以匹配实际字段。

[必须修改] 3. ER图中"图像信息"实体所描述的独立图像表在实际中不存在
   论文有表4.2"图像表"，含 tree_id 外键、image_path、hash_code、hash_bits 字段。
   但实际系统中没有独立的图像表，image_path 和 hash_code 直接存储在 tree 表中。
   ER图中 Tree "1" -- "N" Image 的关系（一对多）与实际一对一（或融合存储）不符。
   建议方案（二选一）：
     方案A：修改论文，删除独立的"图像表"，将 image_path 和 hash_code 合并到树木表中，
            ER图同步删除Image实体，在Tree实体中增加 image_path 和 hash_code 字段。
     方案B：修改代码，新建独立的 image 表，将 image_path 和 hash_code 迁移过去。
            （此方案改动量大，需同步修改 TreeController、TreeMapper、前端等）
   推荐方案A（论文跟随实现），因为当前实现已为演示就绪，改动量最小。

[可选] 4. ER图中 User 与 Image 之间的"维护"关系在论文文字中未说明
   文字描述中未提及用户维护图像的关系，建议在4.2.3节补充说明，
   或从ER图中删除该关系以保持简洁。

二、树木表（表4.3）与实际 tree 表结构严重不一致
================================================================================

[必须修改] 5. 主键类型不一致
   论文表4.3：id 为 bigint（自增主键）
   实际DDL：  id 为 varchar(20)（古树编号，如'001'）
   建议：修改论文表4.3，将 id 改为 varchar(20)，描述改为"古树编号"，
         并说明采用业务编码作为主键，便于与前端展示和图像目录命名对齐。

[必须修改] 6. 字段缺失/多余问题（论文与实际对比）

三、数据库设计文字描述（4.2.3节）不一致
================================================================================

[必须修改] 8. 4.2.3节"本系统主要涉及4张核心数据库表"与实际不符
   论文说有4张表：用户信息表、图像表、树木表、权限角色表。
   实际有（从代码可确认）：
     · user 表（用户信息表）
     · tree 表（树木表，含图像路径和哈希码）
     · 没有独立的 image 表
     · 没有 role 表（代码中未找到Role实体/Mapper/Controller）
   建议修改4.2.3节文字，说明本系统核心表为2张（用户表、树木表），
   图像数据和哈希码直接存储在树木表中，以简化数据模型、减少关联查询。
   或补充说明权限角色表为预留设计，当前版本采用简化方案。

[必须修改] 9. 外键关系描述与实际不符
   论文说："图像表通过tree_id外键与树木表建立关联"
   实际：无图像表，无此外键。
   建议：随图像表的删除同步删除此外键描述。

四、接口路径与时序图不一致
================================================================================

[必须修改] 10. 图4.7时序图接口名与实际不符
   论文图4.7描述：前端 POST 调用 /tree/retrieve 接口，
                   经 TreeRetrieveController → ITreeRetrieveService → TreeRetrieveMapper
   实际代码中：接口为 TreeController，无 /tree/retrieve 路径。
   实际可用接口：
     · GET  /tree/list          — 获取全部古树列表
     · GET  /tree/searchByName  — 按名称条件检索
     · POST /tree/upload        — 图像上传（用于I2I/I2L）
     · GET  /tree/image/{id}    — 获取古树图片
     · GET  /tree/detail/{id}   — 获取古树详情
   建议：修改图4.7时序图，将 /tree/retrieve 改为 /tree/upload + /tree/list 的组合流程，
         或改为描述 /tree/searchByName 的条件检索时序。
         Controller名改为 TreeController，Service/Mapper名改为 TreeService/TreeMapper。

[必须修改] 11. 性能测试表4.8中的 /tree/retrieve 接口不存在
   表4.8列出的接口 /tree/retrieve 在实际中不存在。
   建议：将性能测试接口改为 /tree/upload 或 /tree/searchByName，
         或说明检索接口为演示版固定数据返回，性能数据仍为预估值。

[可选] 12. 用户信息模块时序图（图4.5）接口路径待确认

   实际UserController中：/user/list, /user/login, /user/save 等，
   无明确的 /user/getUserInfo/{userId} 接口。
   建议：核对图4.5与实际UserController接口是否一致，必要时修改。

五、用户信息表（表4.1）与实际可能不一致
================================================================================

[可选] 13. 用户密码加密算法不一致
   论文4.1.1节和表4.1描述：密码通过 bcrypt 哈希算法加密存储。
   实际 UserController.java 第52行：使用 DigestUtils.md5DigestAsHex 进行 MD5 加密。
   建议：统一为 bcrypt（论文改MD5）或统一为MD5（代码改bcrypt）。
   若代码改动困难，论文中应修改为MD5，并说明为不可逆哈希存储。

[可选] 14. 用户信息表字段待核对
   论文表4.1包含：age, desc, per_role_id, is_delete, create_time, update_time
   从UserController看，实际用户查询返回 UserQueryResp，字段需进一步核对。
   建议：确认实际user表字段，确保表4.1与数据库一致。

[可选] 15. 权限角色表（表4.4）在实际中未找到对应实体
   代码中未找到Role.java、RoleMapper等文件，RBAC实现待确认。
   建议：确认当前系统是否已实现角色权限表，若未实现，
         论文中应说明为预留设计或当前采用简化权限控制。
