一、ER图（图4.4-横向版v5-彩色.puml）与论文数据表不一致
================================================================================

[必须修改] 1. ER图 Tree 实体字段严重缺失
   论文表4.3字段（10个）：id, latitude, longitude, age, height, species, desc,
                         is_delete, create_time, update_time
   ER图 Tree 实体只显示5个：树种名称、树龄、树高、纬度、经度
   缺失：id(PK)、desc、is_delete、create_time、update_time
   修改位置：图4.4 PlantUML 中 Tree entity 定义，补充全部字段。

[必须修改] 2. ER图 Image 实体缺少主键 id
   论文表4.2字段：id(PK), tree_id(FK), image_path, hash_code, hash_bits
   ER图 Image 实体只显示：tree_id, 存储路径, hash_code, hash_bits
   缺失：id(PK)
   修改位置：图4.4 PlantUML 中 Image entity 定义，补充 id : bigint <<PK>>。

[必须修改] 3. ER图 User 实体字段严重不足
   论文表4.1字段（10个）：id, username, password, nickname, age, desc,
                         per_role_id, is_delete, create_time, update_time
   ER图 User 实体只显示4个：id(PK)、用户名、密码、个人描述
   缺失：nickname, age, per_role_id, is_delete, create_time, update_time
   修改位置：图4.4 PlantUML 中 User entity 定义，补充全部字段。

[必须修改] 4. ER图 Role 实体字段缺失
   论文表4.4字段（6个）：id, role_name, permission_desc, is_delete,
                         create_time, update_time
   ER图 Role 实体只显示3个：id(PK)、角色名称、权限描述
   缺失：is_delete, create_time, update_time
   修改位置：图4.4 PlantUML 中 Role entity 定义，补充缺失字段。

[论文补漏] 5. 论文表4.2（图像表）缺少通用审计字段
   现状：论文表4.2只有 id, tree_id, image_path, hash_code, hash_bits
   实际：Image.java / ImageInfoMapper.xml / rebuild_tables.sql 均包含
         is_delete, create_time, update_time
   原因：Role表（表4.4）明确包含这3个字段，图像表作为同等地位的业务表，
         应具备统一的逻辑删除和时间戳字段。
   建议：论文表4.2补充 is_delete、create_time、update_time 三个字段，
         使4张核心表设计统一。

[论文补漏] 6. 论文表4.3（树木表）缺少 tree_code 业务编号字段
   现状：论文表4.3没有 tree_code 字段
   实际：Tree.java / TreeMapper.xml / rebuild_tables.sql 均包含 tree_code
         TreeController 中大量使用 treeCode（/tree/image/{treeCode}、
         selectByTreeCode("001") 等），演示数据 001-008 依赖 tree_code
   建议：论文表4.3补充 tree_code 字段（类型 varchar(20)，非空，业务编号），
         并在文字描述中说明其作用（与前端展示和图像目录命名对齐）。
         若论文不补充此字段，则需重写 TreeController 全部检索逻辑，
         改动量远大于改论文。

                  latitude(BigDecimal), longitude(BigDecimal), desc,

   结论：仅需论文补充 tree_code 字段即可完全对齐。

[已对齐] 8. Image 实体/Mapper/DDL 基本对齐论文
   Image.java 字段：id, treeId, imagePath, hashCode, hashBits(byte[]),
                    isDelete, createTime, updateTime
   rebuild_tables.sql / ImageInfoMapper.xml 已完全对应。
   结论：仅需论文表4.2补充 is_delete/create_time/update_time 即可完全对齐。

[已对齐] 9. Role 实体/Mapper/DDL 已对齐论文
   Role.java 字段：id, roleName, permissionDesc, isDelete, createTime, updateTime
   rebuild_tables.sql / RoleMapper.xml 已完全对应。
   结论：✓ 完全对齐，无需修改。

[必须修改] 10. User 实体/Mapper/DDL 与论文表4.1严重不符
   论文表4.1字段（10个）：
     id, username, password, nickname, age, desc,
     per_role_id, is_delete, create_time, update_time
   实际 User.java 字段（4个）：
     id, loginName, name, password
   实际 user 表字段（table.sql / UserMapper.xml）：
     id, login_name, name, password
   实际 UserController 接口：/user/list, /user/save, /user/login,
                           /user/delete/{id}, /user/reset-password, /user/logout
   分析：user 模块为 wiki 原系统遗留，涉及登录认证、用户管理全链路。
         若要代码完全对齐论文，需重写 User.java、UserMapper.xml、
         UserService、UserController 及 user 表，改动量极大且风险高。
   建议（最小改动原则）：
     方案A（推荐）：修改论文表4.1，简化为实际存在的字段：
       id(bigint PK), login_name(varchar50), name(varchar50), password(char32)
       并在4.2.3节文字中说明：用户信息表为系统基础账户表，
       RBAC权限控制通过 per_role_id 字段扩展实现，当前版本采用简化设计。
     方案B：保持论文不变，代码侧重建 user 表并扩展 User.java 字段。
       （此方案需修改登录/注册/用户管理全链路，不建议在答辩前实施）

[必须修改] 11. 密码加密算法描述不一致
   论文4.1.1节和表4.1描述：密码通过 bcrypt 哈希算法加密存储
   实际 UserController 第52行：使用 DigestUtils.md5DigestAsHex 进行 MD5 加密
   建议：修改论文为 "密码通过 MD5 哈希算法加密存储"，并说明为不可逆哈希。
       （代码改动需替换全部用户密码，风险高，不建议）

三、时序图与实际代码不一致

[必须修改] 12. 图4.7 古树名木检索时序图类名与实际不符
   论文描述：前端 POST /tree/retrieve
             → TreeRetrieveController
             → ITreeRetrieveService
             → TreeRetrieveMapper
   实际代码：前端 POST /tree/retrieve
             → TreeController.retrieve()
             → 【无 Service 层，Controller 直接调用 Mapper】
             → TreeMapper
   建议修改：
     (1) Controller 名称改为 TreeController
     (2) 删除 ITreeRetrieveService 层（或增加一层薄薄的 TreeService 做转发，
         但答辩前新增 Service 层改动意义不大，建议直接删除时序图中 Service 层）
     (3) Mapper 名称改为 TreeMapper
     (4) 文字描述同步修改："请求经 TreeController 路由至 TreeMapper..."

[必须修改] 13. 图4.5 用户信息时序图接口路径不存在
   论文描述：/user/getUserInfo/{userId}
   实际接口：/user/list（分页查询）、/user/login（登录）
   建议：将时序图接口改为 /user/list，或删除该时序图（用户信息管理非核心功能）。

[已对齐] 14. 表4.8 性能测试接口 /tree/retrieve 已存在
   TreeController 中确有 @PostMapping("/retrieve") 方法，接口路径正确。
   性能数据为 JMeter 预估值，论文中已说明测试方法，无矛盾。
