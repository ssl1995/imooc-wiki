一、核心结论
================================================================================
图4.5 时序图存在 6 处与代码不符的问题，其中 3 处为接口/方法名错误，
1 处为参数错误，1 处为返回类型错误，1 处为逻辑完全虚构（alt分支）。

================================================================================
二、具体问题清单
================================================================================

【问题1】接口路径不存在（严重）
─────────────────────────────────────────
论文时序图：UserPage → Controller: 调用 /user/getUserInfo/{userId} (GET)
实际代码：   UserController 中只有 @GetMapping("/list")

差异分析：
  • 论文接口：/user/getUserInfo/{userId}，路径参数 userId，GET 请求
  • 实际接口：/user/list，查询参数（loginName, page, size），GET 请求，分页返回

修改建议：
  将时序图接口改为 /user/list，参数改为 UserQueryReq（含 loginName 关键词、
  page 页码、size 每页条数）。

【问题2】Service 方法名不存在（严重）
─────────────────────────────────────────
论文时序图：Controller → Service: getUserInfoByUserId(userId)
实际代码：   userService.list(req)  // req 为 UserQueryReq

差异分析：
  • 论文方法：getUserInfoByUserId(Long userId)，返回单个用户信息
  • 实际方法：list(UserQueryReq req)，返回 PageResp<UserQueryResp>（分页列表）

修改建议：
  Service 调用改为 list(req)，参数为 UserQueryReq 对象。

【问题3】Mapper 方法名不存在（严重）
─────────────────────────────────────────
论文时序图：Service → Mapper: selectUserInfoByUserId(userId)
实际代码：   userMapper.selectByExample(userExample)

差异分析：
  • 论文方法：selectUserInfoByUserId，自定义单条查询
  • 实际方法：MyBatis Generator 生成的 selectByExample，条件分页查询

修改建议：
  Mapper 调用改为 selectByExample(userExample)。

【问题4】alt 分支逻辑完全虚构（严重）
─────────────────────────────────────────
论文时序图：
  alt 管理员角色
      Service → Mapper: selectAllUsers()  // 全量查询
  else 普通用户
      Service → Service: 根据userId过滤当前用户

实际代码：
  • UserServiceImpl.list() 方法中没有任何角色判断逻辑
  • 对所有调用者统一执行：
    1. 创建 UserExample
    2. 若 loginName 非空则添加等值条件
    3. PageHelper.startPage(req.getPage(), req.getSize())
    4. userMapper.selectByExample(userExample)
    5. 返回分页结果

  • 权限控制不在 Service 层，而在前端：
    - the-header.vue 中 perRoleId === 1 才展示"用户管理"菜单
    - 普通用户根本进不了用户管理页面，不存在"普通用户仅返回自身信息"的场景

修改建议：
  删除 alt 分支。实际流程为单次查询+分页，无角色分支。
  若需体现 RBAC，将权限控制逻辑移至前端菜单渲染环节（非本时序图范围），
  或在 note 中说明"前端根据角色控制菜单显隐，管理员方可进入本页面"。

【问题5】返回类型错误
─────────────────────────────────────────
论文时序图/文字："返回用户详情""返回用户数据（ID/登录名/用户名/角色等）"
实际代码：返回 PageResp<UserQueryResp>（含 total 总条数、list 用户列表、
          pages 总页数），非单条用户详情。

修改建议：
  时序图返回数据改为分页结构（列表+总条数+总页数）。

【问题6】前置条件不准确
─────────────────────────────────────────
论文 note："用户已完成登录并携带有效Cookie/Token"
实际代码：使用 Redis 存储 Token，有效期 24 小时。

修改建议：
  可保留 Token 描述，或简化为"用户已完成登录并携带有效 Token"。

三、修改方向（时序图重构建议）
================================================================================

方案A：修改为实际的分页查询流程（推荐）
─────────────────────────────────────────
参与者（6个，不变）：
  用户、用户信息页、UserController、IUserService、UserMapper、MySQL数据库

核心流程（删除 alt 分支，改为单次查询）：
  1. 用户 → 用户信息页：访问用户信息页面
  2. 用户信息页 → UserController：GET /user/list?loginName=xxx&page=1&size=10
  3. UserController → IUserService：list(UserQueryReq)
  4. IUserService → UserMapper：selectByExample(UserExample)
  5. UserMapper → MySQL：执行分页查询（含 PageHelper 拦截）
  6. MySQL → UserMapper：返回用户数据列表
  7. UserMapper → IUserService：返回 List<User>
  8. IUserService → IUserService：CopyUtil.copyList 转换为 UserQueryResp
  9. IUserService → UserController：返回 PageResp（含 list + total + pages）
 10. UserController → 用户信息页：返回 JSON 分页响应
 11. 用户信息页 → 用户：渲染用户信息表格（含分页组件）

注：
  • 步骤 8 中 Service 层还关联查询 role 表填充 roleName（遍历 list 逐个查询）
  • 前端表格展示：登录名、姓名、年龄、角色、用户介绍、上次登录时间、操作列

方案B：删除图4.5（次选）
─────────────────────────────────────────
用户信息管理为非核心功能，已有图4.6页面截图佐证。
若时序图修改后仍无法准确反映代码逻辑，可直接删除图4.5，
在文字中简化为"前端调用 /user/list 分页接口获取用户数据"即可。

四、文字描述同步修改
================================================================================

原文：
  "用户登录后访问用户信息页面，前端GET调用/user/getUserInfo/{userId}接口，
   请求经由UserController路由至IUserService的 getUserInfoByUserId 方法，
   进一步调用UserMapper查询MySQL数据库获取用户详情。
   Service层根据角色进行权限控制：管理员角色触发全量用户查询，
   返回全部用户列表；普通用户则仅返回当前登录用户信息。"

修改为：
  "用户登录后访问用户信息页面，前端GET调用 /user/list 分页接口，
   请求经由 UserController 路由至 UserService 的 list 方法。
   Service 层构建查询条件并调用 UserMapper 的 selectByExample 方法
   查询 MySQL 数据库，返回分页用户列表。
   前端根据 RBAC 权限模型控制菜单显隐：仅管理员角色可进入用户管理页面。"
