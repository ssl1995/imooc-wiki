说明：代码实际使用 MD5(hexMd5(password + "!@#QWERT"))，不改论文则密码逻辑与描述矛盾。

【代码改动清单】（若严格执行以论文为准）

   login_name→username；name→nickname；password char(32)→varchar(128)
2. User.java：loginName→username；name→nickname；增加 isDelete/createTime/updateTime
3. UserMapper.xml：全部字段名替换，增加新字段映射
4. UserController.java：login() / save() / list() 中字段引用同步修改
5. UserService.java / UserServiceImpl.java：同步修改
6. UserLoginResp.java / UserQueryResp.java：如有字段引用，同步修改
7. 前端 the-header.vue / admin-user.vue：login_name → username
8. 数据库：重建 user 表，重新插入测试数据

⚠️ 风险：user 表为 wiki 原系统遗留，涉及登录/注册/用户管理全链路，
   上述改动触及前端+后端+数据库+测试数据，极易引入bug。
   建议：论文表4.1字段向实际代码对齐（改论文而非改代码），

【不一致项】
┌──────────────┬──────────────┬─────────────────────────────────────────────┐
│ 论文         │ 实际         │ 说明                                        │
├──────────────┼──────────────┼─────────────────────────────────────────────┤
│ 无 tree_code │ 有 tree_code │ 业务编号（001-008），演示数据核心依赖字段    │
│ 无 name      │ 有 name      │ 古树名称（如"景山万春亭古柏"），前端展示必备 │
└──────────────┴──────────────┴─────────────────────────────────────────────┘

【修改建议】
⚠️ 强烈建议【论文补充】tree_code 和 name 两个字段：
  • tree_code：varchar(20)，非空，古树业务编号（001、002...）
  • name：varchar(100)，非空，古树中文名称

理由：
1. 演示数据 8 条古树记录全部使用 tree_code（001-008）作为业务标识
2. TreeController 中 /tree/image/{treeCode}、selectByTreeCode 均依赖 tree_code
3. 前端检索结果展示需要 name 字段显示古树名称
4. 若代码侧去掉这两个字段，需重写 TreeController 全部检索逻辑 + 删除/修改
   8 条演示数据 + 修改前端展示逻辑，改动量远大于改论文

【若坚持代码向论文对齐】需修改：
1. create_table.sql：删除 tree 表的 tree_code 和 name 字段
2. Tree.java：删除 treeCode 和 name 属性
3. TreeMapper.xml：删除两个字段映射
4. TreeController.java：
   - 删除 generateTreeCode() 方法
   - 修改 toTreeRetrieveResp() 中 image 路径构造逻辑
   - 修改 save() 中 treeCode 生成逻辑
   - 修改 /tree/image/{treeCode} 接口
5. 演示数据：8 条 INSERT 语句重写
6. 前端：检索结果页去掉古树名称展示
